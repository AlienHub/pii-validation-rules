# Lua 受限正则子集匹配器（`lua/pii/syntax.lua`）

## 为什么存在

规则的权威表达是 PCRE2 正则 `\A(?:body)\z`。Lua 标准库的 pattern（`string.match`）**不是正则**：没有交替、没有 `{n,m}`、字符类语义不同，用它跑这些正则会得到错误结果。为了让纯 Lua 调用方不依赖 C 绑定也能做同样的全串形状检查，本模块实现了一个**只覆盖规则实际用到的构造**的小型匹配器，并用差分测试证明它在整个语料上与原生 PCRE2 判定一致。

它不是 PCRE2 的替代品。遇到子集之外的任何构造，`syntax.compile` 直接抛出 `unsupported_regex_construct`，不会退化为近似匹配。

## 支持的构造

| 构造 | 示例 | 限制 |
|---|---|---|
| 包装 | `\A(?: … )\z` | 必需；只接受这一种锚定形式 |
| 交替 | `a\|b\|c` | 在包装内或 `(?: )` 内 |
| 非捕获分组 | `(?:SG\|OG)` | 分组上不能有量词 |
| 字符类 | `[0-9]`、`[A-HJ-NP-Z]`、`[0-9A-Z<]` | 仅 ASCII；不支持取反 `[^…]`、类内转义 |
| 字面量 | `A-Z a-z 0-9 <`，转义 `\+ \- \. \( \) \/ \<` | 其他元字符报错 |
| 量词 | `{n}`、`{n,m}` | 仅作用于类或字面量；`n,m ≤ 256`；不支持 `*`、`+`、`?`、`{n,}` |
| 不支持 | `\d \w \s`、`.`、`^ $`、前瞻/后顾、反向引用、捕获组、修饰符 | 全部报错 |

## 语义

- 逐**字节**匹配；任何 ≥ 0x80 的字节（即任何非 ASCII 的 UTF-8 字符：全角数字、阿拉伯-印度数字、零宽字符、双向控制符）都不在任何类中，因此永远不匹配。这与 PCRE2 在 options=0 与 PCRE2_UTF 下对这些模式的判定一致（规则只用 ASCII 类）。
- `\z` 语义：末尾换行不匹配（与 `$` 不同）。
- 回溯：量词贪婪并在边界内回退；因为所有重复都有上界且没有嵌套量词，最坏复杂度受规则长度限制，不存在灾难性回溯。
- 匹配前先按模式推导的最小/最大长度快速拒绝。

## 验证方式

1. `tests/lua/suite_syntax_subset.lua`：129 条规则全部可编译；一组子集外模式必须报错；规则样本与反例的判定与 PCRE2 预期一致。
2. 差分：`fixtures/regex-differential-corpus.json`（7363 个合成输入：样本、截断、增删、替换、大小写翻转、Unicode 数字、零宽/双向字符、换行）由原生 PCRE2（`tests/pcre2/run_pcre2_tests.py`）与 Lua 匹配器分别判定，`tools/compare_syntax_verdicts.py` 比对，结果在 `reports/lua-vs-pcre2-differential-<runtime>.json`。本次提交：3 个运行时 × 7363 输入，0 分歧。

## 如果需要完整 PCRE2

在 Lua 中运行任意 PCRE2 请显式引入绑定（例如 `lrexlib-pcre2`）并自行测试依赖与版本；可以用 `rule.regex_pcre2` 原样喂给它。本仓库不隐式依赖任何 C 绑定，也不会把 `string.match` 伪装成正则引擎。
